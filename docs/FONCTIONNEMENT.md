# HypnoMorphosis · Fonctionnement technique

## Stack

- Next.js 16 (App Router), React 19, TypeScript
- Tailwind CSS 4
- pnpm
- Hébergement : Vercel (projet `hypnomorphosis`, équipe Agon-gate), déploiement automatique depuis GitHub (`agon-gate-pro/hypnomorphosis`, branche `main`)
- Comptes clients : Clerk (`@clerk/nextjs` 7), application `hypnomorphosis-clerk` créée par l'intégration Vercel Marketplace dans l'espace Clerk « Agon-gate ». L'intégration pose `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` et `CLERK_SECRET_KEY` dans Vercel (non sensibles, pour pouvoir les récupérer avec `vercel env pull`) ; ne pas les modifier à la main
- Fichiers des expériences : Vercel Blob, store **privé** `hypnomorphosis-contenus` (région Paris `cdg1`), créé le 2026-10-29 et relié au projet dans les trois environnements (`BLOB_READ_WRITE_TOKEN`). Un fichier par expérience sous le dossier de son slug : `decouverte/audio-1.mp3`, `decouverte/audio-2.mp3`, `decouverte/carnet-decouverte.pdf`. Envoi d'un fichier : SDK `put(chemin, contenu, { access: "private", addRandomSuffix: false, allowOverwrite: true })` avec le jeton de `.env.local` (le découpage `multipart` restait bloqué ; `vercel blob put -t` est pris pour l'option `--token` du CLI)

## Structure

- `app/` : pages et layout (App Router). `page.tsx` : accueil ; `derriere-hypnomorphosis/` : page « Derrière HypnoMorphosis » (texte de Bérénice et studio) ; `connexion/` et `inscription/` : formulaires Clerk ; `espace/` : Mon espace, et `espace/compte/` : gestion du compte (écran Clerk) ; `espace/experiences/[slug]/` : intérieur d'une expérience ouverte (carnet et audios) et sa route `fichiers/[fichier]` ; `experiences/[slug]/` : fiche d'une expérience payante, générée au build pour chaque expérience de `lib/experiences.ts` ; `not-found.tsx` : page 404 ; `robots.ts`, `sitemap.ts` et `llms.txt/route.ts` : fichiers pour les robots, générés depuis `lib/experiences.ts` et `lib/site.ts` ; `layout.tsx` : polices (next/font : Cormorant Garamond, Jost, Marcellus), métadonnées, `noindex`, `ClerkProvider` avec les textes français et l'habillage ; `globals.css` : styles de l'accueil repris de la maquette ; `icon.svg` : favicon (emblème) ; `opengraph-image.tsx` : carte de partage générée au build
- `components/` : `EnTete.tsx` (en-tête et menu plein écran, composant client, pastille au prénom une fois connectée), `PiedDePage.tsx`, `Apparitions.tsx` (apparition au défilement), `Icones.tsx` (icônes au trait), `CadreConnexion.tsx` (écran de connexion et d'inscription), `GardeClerk.tsx` (rechargement si Clerk ne s'affiche pas), `BoutonDeconnexion.tsx`, `LecteurAudio.tsx` (lecteur maison : lecture, pause, barre d'avance), `DonneesStructurees.tsx` (balise JSON-LD)
- `lib/site.ts` : adresse du site (`urlSite`, seul endroit à changer pour le passage au .com), métadonnées par page (`metaPage`), descriptions schema.org de la marque et de Bérénice, liens partagés (article Madame Figaro, réseaux sociaux : un réseau sans adresse n'est affiché nulle part)
- `lib/contenus.ts` : liens signés vers le store privé (1 h)
- `lib/experiences.ts` : liste provisoire des expériences et textes de leurs fiches (passages en gras entre `**`), en attendant la base de données
- `proxy.ts` : contexte d'authentification Clerk (aucune route n'y est protégée)
- `assets/` : fichiers lus côté serveur, non publiés (police Marcellus et sa licence OFL pour l'image de partage)
- `public/` : fichiers statiques (`logo/` : logo et emblème SVG ; `images/` : couvertures de l'expérience découverte, du Nœud et d'Après nous, portrait de Bérénice, fauteuil du studio)
- `docs/` : documentation du projet (`SITE INTERNET.pdf` : brief du client ; `specification-fonctionnelle.md` : ce que le site doit faire ; `Echange Mail 01.txt` et `Echange Mail 02.txt` : réponses de Bérénice ; `HYPNOMORPHOSIS.pdf` : carnet de l'expérience découverte ; logos en JPG, logo vectorisé dans `logo/`, `couverture-decouverte.jpg`, photos de Bérénice, détaillés dans la section 10 de la spécification ; `maquette-accueil-1-carnet.html` : maquette d'accueil retenue)

Trois polices au lieu de quatre (Newsreader remplacée par Cormorant Garamond italique). Images via `next/image` (dimensions fixes, formats optimisés). Site non référencé tant qu'il n'est pas lancé : `robots: { index: false }` dans les métadonnées, sans `robots.txt` bloquant (un robot bloqué ne lirait pas le `noindex`). Image de partage 1200 × 630 générée par `next/og` : emblème, nom et slogan en Marcellus, couverture de l'expérience découverte ; chemins des fichiers écrits en entier pour que le build n'embarque pas tout le projet. Liens « Je découvre », « Mon espace », fiches et réseaux sociaux encore vides (`#`).
- 2026-10-27 : finitions de la maquette, à reprendre dans le site. En-tête en verre dépoli (`backdrop-filter`) avec ombre après le haut de page ; `scroll-margin-top` sur les sections pour que les ancres s'arrêtent sous l'en-tête fixe. Menu plein écran sur téléphone, placé hors de l'en-tête (un parent avec `backdrop-filter` enfermerait un élément `position: fixed`), fermé par le bouton, un lien ou Échap. Apparition des blocs au défilement par `IntersectionObserver`, en cascade dans une même rangée ; la classe `js` est posée dans le `<head>` pour que la page reste lisible sans script et sans clignotement. - 2026-10-28 : « Grandes expériences » retirées de l'affichage tant que la catégorie est vide (demande de Bérénice) ; la boutique n'affichera que les catégories qui ont au moins une expérience. Couvertures des carnets en fond des cartes (`next/image` en `fill`, `object-fit: cover`), voile dégradé en haut et en bas pour lire la catégorie et le titre en clair. - 2026-10-28 : en-tête sur téléphone. Sous 640 px, nom, emblème et hauteur réduits (64 px, `scroll-margin-top` suivi). Sous 380 px, le mot du bouton Menu ou Fermer (`.mot`) est masqué visuellement mais pas pour les lecteurs d'écran. Le bouton ne rétrécit jamais (`flex-shrink: 0`). La barre du menu plein écran a `width: 100%` : dans une colonne flex, les marges auto du `.wrap` la réduisaient à son contenu.
- 2026-10-29 : comptes clients avec Clerk (branche `comptes`), sur le modèle de Set et Brique. Connexion sans mot de passe : code à 6 chiffres reçu par e-mail, ou compte Google. Prénom et nom demandés à l'inscription (« Require first and last name » : Clerk ne permet pas d'exiger le prénom seul). Pages `/connexion` et `/inscription` (composants `SignIn` et `SignUp` dans `CadreConnexion` : couverture de l'expérience découverte à gauche, masquée sous 900 px, formulaire posé sur le papier sans cadre ni ombre), `/espace` (Mon espace : « Bonjour, Prénom », expériences ouvertes, expériences à découvrir) et `/espace/compte` (`UserProfile` de Clerk dans un composant client, hauteur libérée comme sur Set et Brique). Habillage par l'`appearance` du `ClerkProvider`, avec les variables Clerk récentes (`colorForeground`, `colorMutedForeground`, `colorInput`…, et non `colorText` comme sur Set et Brique) : olive, papier, Cormorant pour les titres, boutons droits en capitales. Textes `frFR` avec des titres maison (« Bon retour parmi nous », « Créer mon espace ») qui évitent le nom technique de l'application Clerk, et le rappel des spams à l'étape du code. Chaque page privée appelle `auth.protect()` ; `clerkMiddleware` reçoit `signInUrl: "/connexion"` (sans cela, `auth.protect()` renvoie vers la page hébergée par Clerk, le réglage du `ClerkProvider` ne valant que dans le navigateur). Après connexion ou inscription, arrivée sur `/espace`. Les liens « Je découvre HypnoMorphosis gratuitement » de l'accueil mènent à `/inscription`. Liens internes en `next/link`, ancres en `/#…` pour fonctionner hors de l'accueil. Les expériences ouvertes ne sont pas encore enregistrées : tout compte voit l'expérience découverte (`lib/experiences.ts`) ; la page intérieure d'une expérience est la prochaine étape.
- 2026-10-29 : fiches des expériences. Une route `/experiences/[slug]` générée au build (`generateStaticParams`, `dynamicParams = false`) pour les expériences payantes ; la découverte n'a pas de fiche, ses liens mènent à `/inscription`. Textes de Bérénice repris mot pour mot du brief, rangés dans `lib/experiences.ts` pour passer tels quels en base plus tard. Bouton d'achat inactif tant que Stripe n'est pas branché. Réseaux sociaux : rien n'est affiché sans adresse, pour qu'aucun lien ne mène nulle part. Page 404 maison (`app/not-found.tsx`). Classe de l'écran de connexion renommée `.acces-page` : `.acces` touchait aussi la liste `ul.acces` de l'accueil.
- 2026-10-29 : référencement et lisibilité par les IA, préparés avant le lancement. Audit : tout le texte est rendu côté serveur (lisible par les robots qui n'exécutent pas le JavaScript, comme GPTBot ou ClaudeBot) ; titres, H1 et H2, textes alternatifs corrects. Corrigé : chaque page publique a son titre, sa description, son adresse canonique et son aperçu de partage (`metaPage`) ; l'aperçu de l'accueil était repris partout. L'image de partage est redonnée dans chaque `openGraph` de page : une page qui définit le sien ne reprend plus celle de `app/opengraph-image.tsx`. Données structurées schema.org : `Organization`, `WebSite`, `Person` (Bérénice Hervet, nom complet ajouté à la demande d'Alexis et affiché sur Derrière HypnoMorphosis comme le demande Google, lien vers l'article Madame Figaro) et `ItemList` sur l'accueil, `ProfilePage` sur Derrière HypnoMorphosis, `Product` avec son offre (49 EUR, en `PreOrder` tant que l'achat n'est pas ouvert) sur les fiches. `robots.txt` ouvert à tous les robots sauf `/espace/` (le `noindex` des pages reste ce qui bloque le référencement : un robot bloqué ne le lirait pas), `sitemap.xml`, et `llms.txt` (résumé du site pour les IA). Espace ajouté dans le titre de l'accueil, lu « champde » par certains robots.
- 2026-10-29 : intérieur de l'expérience découverte (`/espace/experiences/decouverte`), d'après la décision prise avec Madus : Vercel Blob privé, aucune URL publique, liens signés d'environ 1 h générés après vérification des droits. Les fichiers ne passent pas par une fonction : la page pointe vers `/espace/experiences/[slug]/fichiers/[fichier]`, qui vérifie la connexion (`auth()`, 401 sinon), que l'expérience est ouverte à la cliente et que le fichier est déclaré dans `lib/experiences.ts` (404 sinon, aucun autre chemin du store n'est atteignable), puis répond par une redirection 302 vers un lien signé neuf (`issueSignedToken` limité au fichier et à la lecture, puis `presignUrl`), en `Cache-Control: private, no-store`. Le lien n'apparaît donc jamais dans la page et ne périme pas si elle reste ouverte. Vérifié : lien signé et lecture partielle (`Range`, réponse 206, avance rapide dans le lecteur), URL sans signature refusée (403), signature d'un fichier refusée pour un autre (403). Jeton du store passé explicitement au SDK : sans lui, le SDK tente l'OIDC et exige `BLOB_STORE_ID`. `proxy.ts` : `/espace/:path*` ajouté au filtre, qui excluait les adresses en `.mp3` et `.pdf` (Clerk ne voyait pas la route des fichiers). Audios en écoute seule tant que Bérénice n'a pas tranché le téléchargement ; carnet PDF ouvert dans un nouvel onglet, donc téléchargeable.

## Outils Claude Code

Partagés par le dépôt : chacun les récupère en ouvrant le projet dans Claude Code (une approbation est demandée la première fois).

| Fichier | Contenu |
| --- | --- |
| `.mcp.json` | Serveurs MCP : Playwright (navigateur piloté, captures et tests de parcours, sur Microsoft Edge) et Context7 (documentation à jour des bibliothèques) |
| `.claude/settings.json` | Plugins `frontend-design` (marketplace officielle Anthropic) et `agon-gate` (outils maison, marketplace privée `agon-gate-pro/agon-gate-outils`) |
| `.claude/skills/` et `skills-lock.json` | Skills Clerk (setup, Next.js, webhooks, API), Neon Postgres, Stripe, web-design-guidelines (Vercel) |

- Les skills sont installés en copies réelles (`npx skills add <source> -s <skill> -a claude-code --copy -y`) : les liens symboliques créés par défaut ne fonctionnent pas sous Windows (constaté sur Set et Brique, où `.claude/skills` contient des fichiers de 38 octets à la place des skills).
- Playwright est lancé via `cmd /c npx`, nécessaire sous Windows. Sur macOS ou Linux, remplacer par `"command": "npx"` et retirer `/c` dans `.claude/settings.local.json` ou un `.mcp.json` local. Le navigateur est Edge (`--browser msedge`), car Chrome n'est pas installé sur le poste d'Alexis.
- Playwright enregistre captures, journaux de console et instantanés de page dans `.playwright-mcp/` à la racine du projet (seul dossier autorisé en écriture, avec la racine). Ce dossier est ignoré par Git.
- Context7 fonctionne sans clé, avec un quota limité. Une clé gratuite (context7.com/dashboard) peut être ajoutée plus tard.
- Le plugin `frontend-design` n'est pas installé automatiquement par `.claude/settings.json` : chacun l'installe une fois sur son poste, soit avec `/plugin` dans une session (accepter la marketplace `claude-plugins-official`, installer `frontend-design`), soit en ligne de commande depuis le dossier du projet : `claude plugin install frontend-design@claude-plugins-official --scope project`. Redémarrer ensuite la session : le skill `frontend-design` apparaît dans la liste des skills.
- Le plugin `agon-gate` apporte les skills `agon-gate:nouveau-projet` (démarrer ou remettre aux normes un projet client) et `agon-gate:livraison` (checklist de mise en ligne). Il est proposé à l'ouverture du projet. Le dépôt de la marketplace étant privé, il faut un accès GitHub à l'organisation `agon-gate-pro`. Installation manuelle si besoin : `claude plugin marketplace add agon-gate-pro/agon-gate-outils` puis `claude plugin install agon-gate@agon-gate-outils`, et redémarrer la session.
